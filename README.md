# site-template

Шаблон для новых простых сайтов (лендинг, визитка, до ~5 страниц): чистый HTML, CSS и немного JS, без сборки.

Что уже есть:
- адаптивная вёрстка от мобильной версии, токены дизайна (цвета, шрифты, отступы) в начале `assets/css/style.css`;
- шрифт Manrope с кириллицей, лежит в репозитории (без Google Fonts и других CDN), лицензия OFL в `assets/fonts/`;
- мобильное меню (закрывается по Esc, по ссылке и по клику вне), ссылка «перейти к содержимому», видимый фокус;
- анимированные иконки [morphicons](https://www.npmjs.com/package/morphicons): `<morph-icon>` плавно перетекает из одной иконки в другую (в шаблоне так сделан бургер ↔ крестик у меню). Файлы лежат в `assets/vendor/morphicons/` (≈15 КБ в gzip, без сборки и CDN), подключение в `assets/js/icons.js`, как обновить — в `assets/vendor/morphicons/README.md`. Если на сайте анимированных иконок нет, удалите эту папку, `icons.js` и строку с ним в `<head>`;
- у кнопок и ссылок есть состояния наведения, нажатия, фокуса и «недоступна», зоны нажатия от 44 px; нажатие видно и на iPhone;
- окно-шторка на `<dialog class="sheet">` (пример: «Подробнее об услуге»): на телефоне поднимается снизу, на компьютере выезжает справа, без подскока и рамки у «Закрыть», закрывается по Esc и кликом мимо, при выключенных в системе анимациях мягко проявляется на месте. Открывает его кнопка с `aria-haspopup="dialog"` и `aria-controls="<id окна>"`;
- токены движения в `:root`: длительности и кривые для мелочей, окон и крупного текста (`--ease-sheet`, `--ease-soft`, `--duration-sheet-in` и др.);
- форма заявки (`assets/js/form.js`): проверка ввода с понятными ошибками на русском, блокировка двойной отправки, сообщения «отправляем / успех / ошибка сервера / нет сети», данные не стираются при ошибке; согласие по 152-ФЗ и каркас `privacy.html`;
- `title`, `description`, Open Graph, favicon, `robots.txt`, `sitemap.xml`, страница 404, которая работает и на превью;
- автопроверка в каждом pull request (см. ниже) и чек-лист признаков «сайта от нейросети» в `.github/CHECKLIST.md`;
- публикация превью на GitHub Pages через GitHub Actions; превью закрыто от поисковиков (`noindex`), сами файлы сайта остаются открытыми для поиска;
- шаблон pull request со скриншотами 375 / 768 / 1280.
- скиллы Claude в `.claude/skills/`, Claude подхватывает их сам по ходу работы:
  - `web-design-guidelines`: проверка вёрстки по правилам Vercel Web Interface Guidelines (доступность, фокус, формы, анимации, типографика);
  - `emil-design-eng`: правила Эмиля Ковальски для анимаций и «отзывчивости» интерфейса (кривые, длительности, нажатия, всплывающие окна);
  - `review-animations`: строгая проверка анимаций с итогом «блок / одобрено»;
  - `mobile-native`: мелкие правки, чтобы сайт на телефоне ощущался как приложение (100dvh, вырезы экрана, зум полей, вспышки при нажатии).
  - `gsap-core`, `gsap-timeline`, `gsap-scrolltrigger`, `gsap-plugins`, `gsap-utils`, `gsap-react`, `gsap-performance`: официальные шпаргалки GSAP (MIT). Нужны только на сайтах, где выбран GSAP; кривые и длительности берём из наших правил движения, а не из настроек GSAP по умолчанию.

## Новый сайт из шаблона

1. На GitHub: **Use this template → Create a new repository**, имя `site-<название>`.
2. Заменить `example.ru`, тексты, токены в `:root`, favicon и `assets/img/og.jpg` (1200×630).
3. Подключить форму: создать форму на [Formspree](https://formspree.io) и вписать её адрес в `action` вместо `YOUR_FORM_ID` (или свой обработчик). Пока этого нет, форма честно пишет, что не подключена.
4. Заполнить `privacy.html` данными владельца (всё в `[ЗАПОЛНИТЬ: …]`).
5. Включить превью: открыть в браузере `https://github.com/<логин>/<репозиторий>/settings/pages` и в блоке **Build and deployment** в строке **Source** выбрать **GitHub Actions** (сохраняется само). В приложении GitHub на телефоне этой настройки нет, нужен браузер; на телефоне можно включить «Версию для ПК».

## Запуск локально

Сборки нет, нужен любой статический сервер:

```bash
python3 -m http.server 8000
# или
npx serve .
```

Открыть http://localhost:8000.

## Автопроверка

Ловит типичные ошибки: ссылки на `#` и битые ссылки, кнопки без реакции на наведение и нажатие, форму, которая молчит при ошибке или отправляется дважды, меню, которое не закрывается, ошибки в консоли, мелкие зоны нажатия, сломанную 404, заглушки и штампы в текстах. А ещё:

- **размеры экрана** от 320 до 2560 px, ноутбук 1280×630 и масштаб Windows 125 % и 150 %: горизонтальная прокрутка и **наложения** (картинка на тексте, в том числе при наведении; текст на тексте). Задуманное наложение помечается атрибутом `data-overlap-ok`;
- **окна** (`<dialog>`): покадрово следит за выездом (без отката назад, рывка за один кадр и подскока в конце), фокус не на «Закрыть», закрытие по Esc и кликом мимо, поведение без анимаций;
- **движение**: анимации `width`, `letter-spacing` и других свойств, которые пересчитывают страницу, `transition: all`, правило «убрать всё движение» для режима без анимаций;
- **ссылки шире своей надписи** (тап по пустому месту уводит не туда);
- **размеры блоков по сравнению с прошлой версией** (в pull request сравнивает с `main`): картинки, заголовки, секции, которые изменились. Это не ошибка, а список, чтобы сверить, что так и задумано.

Скриншоты: вся страница на 375 / 768 / 1280 и первый экран на 1280×630, 1920×1080 и при масштабе 125 %.

- **В pull request** запускается сама (Actions → «Проверка сайта»). Отчёт в Summary, скриншоты в артефакте `screenshots`.
- **Локально** (нужен Node.js 20+):

  ```bash
  cd .github/check
  npm ci
  npx playwright install chromium   # один раз
  npm run check                     # черновик: заглушки только предупреждают
  npm run check:release             # перед публикацией: заглушки тоже ошибки
  npm run check -- --base /путь/к/прошлой/версии   # плюс сравнение размеров блоков
  ```

  Прошлую версию удобно достать так: `git worktree add /tmp/site-main main`.

  Отчёт и скриншоты появятся в папке `.check/`.

Чего проверка не видит (дизайн, смысл текстов, «шаблонность»), смотрим руками по `.github/CHECKLIST.md`.

## Публикация

- **Превью**: автоматически на GitHub Pages после пуша в `main` (`https://<логин>.github.io/<репозиторий>/`).
  При публикации в каждую страницу превью добавляется `<meta name="robots" content="noindex">`: по ссылке сайт открывается как обычно, но Яндекс и Google его не берут. Иначе недоделанное превью попадёт в поиск раньше запуска, а потом станет дублем боевого домена. В файлах репозитория этой метки нет, на боевой сайт она не попадает. Если превью должно быть в поиске (концепт для портфолио), задайте переменную репозитория `PREVIEW_INDEX` = `true`: Settings → Secrets and variables → Actions → вкладка **Variables**. После сдачи сайта клиенту превью выключить: Settings → Pages → **Unpublish site**.
- **Боевой сайт**: загрузить файлы на российский хостинг (Timeweb, Beget, Reg.ru) по FTP/SFTP или в Yandex Object Storage, без папок `.github`, `.claude`, `.check` и `node_modules`. Настроить на хостинге `404.html` как страницу ошибки 404. Перед этим пройти `npm run check:release`. Только после явного согласия владельца.

## Изображения

Фото и иллюстрации хранить в `assets/img/` в WebP или AVIF, с `width`/`height`, `alt` и `loading="lazy"` (кроме первого экрана). Не ссылаться на картинки со сторонних сайтов.
